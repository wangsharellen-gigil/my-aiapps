创建并上传第一个仓库

这一篇会带你走通两条路：完全在网页上完成，和在自己的电脑上用 Git 完成。建议先走网页版建立直观印象，再走本地流程。

第一步：在 GitHub 上新建仓库

  1. 点击右上角的 ＋ → New repository，或直接访问 github.com/new。
  2. Repository name：仓库名，例如 hello-github。只能用字母、数字、-、_、.。
  3. Description：一句话说明项目用途（可留空）。
  4. Visibility：Public 任何人可见；Private 仅你和被邀请的人可见。练习建议选 Public，因为免费账号的 Pages 只支持公开仓库。
  5. 可选初始化项：
    • Add a README file：生成项目说明文件，强烈建议勾选。
    • Add .gitignore：选择语言模板，自动忽略不该提交的文件（如 node_modules）。
    • Choose a license：开源项目建议选 MIT 或 Apache-2.0。
  6. 点击 Create repository。
说明

如果勾选了 README / .gitignore / 许可证，GitHub 会自动生成一个首次提交，仓库不再是空的。这会影响下面的本地推送步骤：空仓库可以直接推送，已有提交的仓库必须先 git pull 或 clone。

方式一：全程在网页上完成

适合不熟悉命令行、或只想快速上传几个文件的情况。

  1. 在仓库首页点击 Add file → Create new file，输入文件名（如 notes.md），在编辑区写内容。
  2. 向下滚动到 Commit changes，填写提交说明，例如 docs: 添加第一篇笔记。
  3. 点击 Commit changes，文件就进入了仓库历史。

上传已有文件则用 Add file → Upload files，把文件拖进页面即可（单文件不超过 25 MB，单次上传不超过 100 个文件）。

想修改已有文件：打开文件 → 右上角铅笔图标 → 编辑 → 提交。整个过程不需要安装任何软件。

提示

在 GitHub 仓库页面按 .（英文句号）会把仓库切换成完整的网页编辑器（基于 VS Code），可以直接修改多个文件并提交，非常适合临时改文档。

方式二：在本地用 Git 提交

情况 A：仓库是空的（没有 README）

打开终端（Windows 用 Git Bash），进入你想放项目的目录，依次执行：

# 1. 创建项目文件夹并进入
mkdir hello-github
cd hello-github

# 2. 初始化本地仓库
git init

# 3. 创建一个文件
echo "# Hello GitHub" > README.md

# 4. 把改动放入暂存区
git add README.md

# 5. 提交到本地仓库
git commit -m "docs: 添加 README"

# 6. 关联远程仓库（地址从仓库页面 Code 按钮复制）
git remote add origin https://github.com/你的用户名/hello-github.git

# 7. 确保分支名为 main
git branch -M main

# 8. 推送并建立跟踪关系
git push -u origin main

情况 B：仓库已有 README（推荐）

直接克隆到本地，改动后再推送，可以避免历史冲突：

git clone https://github.com/你的用户名/hello-github.git
cd hello-github

# 修改文件后
git add .
git commit -m "docs: 更新项目说明"
git push
注意

如果仓库已有提交，而你又在本地 git init 新建仓库后直接 git push，会被拒绝（rejected ... fetch first）。这不是权限问题，而是两段历史没有共同祖先。解决办法见 常见报错，新手更建议直接用 git clone。

这几条命令到底做了什么

命令作用
git init在当前目录创建一个隐藏的 .git 文件夹，从此这个目录受 Git 管理。
git add .把当前目录所有改动放入暂存区（. 表示全部）。
git commit -m "说明"把暂存区内容打包成一次提交，写入本地历史。
git remote add origin 地址给远程仓库起个别名 origin，之后用这个名字指代它。
git branch -M main把当前分支重命名为 main（Git 旧版本默认是 master）。
git push -u origin main把本地 main 分支推送到远程。-u 记住对应关系，之后只需 git push。
git clone 地址下载整个仓库（含全部历史）到本地，并自动配置好远程地址。

写一份像样的 README

README 是仓库的"门面"，会直接显示在仓库首页。对初学者来说，一份合格的 README 至少包含四部分：

# 项目名称

一句话说明这个项目解决什么问题。

## 功能

- 功能一
- 功能二

## 如何运行

1. 克隆仓库：`git clone https://github.com/用户名/仓库名.git`
2. 打开 `index.html` 即可。

## 许可证

MIT

Markdown 常见语法：# 标题、**加粗**、- 列表、`代码`、[文字](链接)、![图片说明](图片地址)。GitHub 还支持表格、任务列表（- [ ] 待办）和折叠块。

提示

在仓库根目录新建 README.md 后，仓库首页会自动展示它。如果你建一个与自己用户名同名的仓库（如 alice/alice），这个 README 会显示在你的个人主页上，是最简单的"个人名片"。

仓库页面速览

  • Code：文件列表、分支切换、提交历史、克隆地址。
  • Issues / Pull requests：任务与协作入口，默认关闭，可在 Settings 中启用。
  • Actions：自动化流水线，首次配置后才会出现内容。
  • Projects / Wiki：项目管理与文档页。
  • Security / Insights：依赖告警、流量与提交统计。
  • About 区域：右侧可编辑简介、网站、话题标签（Topics），让项目更容易被搜到。
