更多平台功能一览

除了仓库、Issue、PR、Actions、Pages 这五个核心功能，GitHub 还有一整套周边能力。这一篇按用途分组介绍，方便你按需深入。

发布版本：Releases 与 Tag

Tag（标签）是给某次提交起的固定名字，例如 v1.0.0。Release（发布）则是在 Tag 之上加了一层"对外发布说明页"，可以附带编译好的安装包。

  1. 仓库右侧 Releases → Create a new release。
  2. 新建或选择已有 Tag，填写标题与发布说明。
  3. 把构建产物（zip、exe、dmg 等）拖到附件区。
  4. 可以标记为 pre-release（预发布）或 latest（最新稳定版）。
# 命令行打标签并推送
git tag -a v1.0.0 -m "首个正式版本"
git push origin v1.0.0

# 用 gh 直接创建发布并上传文件
gh release create v1.0.0 ./dist/app.zip --generate-notes

包托管：GitHub Packages

可以把依赖包直接发布到 GitHub，与仓库权限打通。支持 npm、Maven、Gradle、NuGet、RubyGems 和容器镜像（ghcr.io）。

# 以容器镜像为例
echo $CR_PAT | docker login ghcr.io -u 你的用户名 --password-stdin
docker tag my-app ghcr.io/你的用户名/my-app:1.0.0
docker push ghcr.io/你的用户名/my-app:1.0.0

公开仓库的包默认公开，私有仓库的包继承仓库权限。发布流程通常写在 Actions 里，随 Tag 自动执行。

代码片段：Gist

Gist 是轻量级的单文件（或多文件）分享工具，自带版本历史、语法高亮和评论区，适合分享配置、脚本、笔记。

  • 访问 gist.github.com 新建，可设置文件名与描述。
  • Secret gist 不会出现在列表和搜索中，但拿到链接的人都能看，不要放密钥。
  • 每个 Gist 都是一个可克隆的 Git 仓库，也可以嵌入网页：<script src="https://gist.github.com/用户/编号.js"></script>。

项目文档：Wiki

仓库自带的文档系统，适合写长篇使用手册、设计文档。在仓库 Wiki 标签页创建首页即可启用，支持 Markdown、侧边栏导航和独立的历史记录。Wiki 也可以克隆到本地编辑：

git clone https://github.com/用户名/仓库名.wiki.git

如果文档需要严格的评审流程，更推荐直接放在仓库的 docs/ 目录里，这样能走 PR 流程。

项目管理：Projects

Projects 是内置的看板/表格工具，可以跨多个仓库汇总 Issue 与 PR。

  • 视图：Table（表格）、Board（看板）、Roadmap（时间线）。
  • 自定义字段：优先级、状态、预估工时、迭代周期。
  • 自动化：Issue 一创建就自动加入项目；状态变化时自动移动卡片。
  • 分组与筛选：按负责人、标签、里程碑切片查看。

适合个人规划"本周要做什么"，也适合团队做迭代管理。入口在个人主页或组织页面的 Projects 标签。

个人主页 README

创建一个与用户名同名的公开仓库（例如用户名 alice，仓库名也叫 alice），并在根目录放 README.md，这段内容就会显示在你的 GitHub 主页顶部。

### 你好，我是 Alice 👋

- 🔭 目前在做一个笔记工具
- 🌱 正在学习 TypeScript 和 Rust
- 📫 联系我：alice@example.com

![GitHub 统计](https://github-readme-stats.vercel.app/api?username=alice&show_icons=true)

另外在主页可以 Pin 最多 6 个仓库作为代表作，并维护 Bio、社交链接和状态（Status）。

GitHub Mobile 与 Desktop

  • GitHub Mobile（iOS / Android）：随时查看通知、审阅 PR、回复 Issue、合并分支，适合碎片时间处理协作事项。
  • GitHub Desktop（Windows / macOS）：图形化 Git 客户端，可视化查看改动、提交、分支与冲突，适合不想背命令的新手。

GitHub CLI（gh）

官方命令行工具，把网页操作搬到终端，适合脚本化和高频操作。

gh auth login                       # 登录并配置凭据
gh repo create 名称 --public --clone  # 新建仓库并克隆
gh issue list --label bug           # 列出 Bug
gh pr create --fill                 # 用提交信息创建 PR
gh pr checkout 123                  # 检出某个 PR 的分支
gh run list                         # 查看 Actions 运行
gh run view --log-failed            # 只看失败步骤的日志

Codespaces：云端开发环境

在浏览器里打开一个配好环境的 VS Code，无需在本地安装任何依赖。适合换设备继续开发、给开源项目做临时贡献、教学演示。

  • 仓库页面 Code → Codespaces → 新建，几十秒即可进入。
  • 用 .devcontainer/devcontainer.json 固化环境（Node 版本、扩展、端口）。
  • 个人账号每月有免费核心小时额度，超出后按量计费，闲置会自动停止。

Copilot：AI 编程助手

GitHub 的 AI 助手，提供代码补全、对话式问答、代码解释与重构建议，可在编辑器、网页和 CLI 中使用。

  • 补全：写注释或函数名时给出整段建议，Tab 接受。
  • Chat：用自然语言询问代码、生成测试、排查报错。
  • 代码评审：可在 PR 中请求 AI 给出评审意见。
  • 学生、教师可通过 GitHub Education 免费使用；免费版每月有一定额度。
注意

AI 生成的代码需要你自行理解并验证，尤其是许可证与安全性。不要把公司密钥、用户数据贴进对话。

安全相关功能

  • Dependabot alerts：依赖出现已知漏洞时提醒你。
  • Dependabot updates：自动提交升级依赖的 PR。
  • Code scanning：用 CodeQL 等工具扫描代码中的安全问题，可在 PR 中拦截。
  • Secret scanning：检测仓库中是否误提交了令牌、密钥；公开仓库免费，支持推送前拦截（Push protection）。
  • Private vulnerability reporting：让安全研究者私下向你报告漏洞。
  • Security advisories：公开披露并修复已知漏洞的正式渠道。

详细配置见安全与最佳实践。

组织、团队与权限

Organization（组织）是多人共管仓库的容器，可以创建 Teams（团队）并给团队而不是个人授权：

  • 仓库角色：Read / Triage / Write / Maintain / Admin。
  • 组织角色：Owner / Member / Billing manager / Security manager。
  • 支持 SAML 单点登录、审计日志、IP 白名单（付费方案）。

个人项目不需要组织；一旦多人协作、需要区分权限时再创建。

通知管理

通知过多是新手放弃 GitHub 的主要原因之一。Settings → Notifications 建议：

  • 只订阅 Participating, @mentions, and team mentions，而不是全部 Watching。
  • 对不关心的仓库取消 Watch（选择 Ignore）。
  • 用 github.com/notifications 的过滤器按原因批量处理。

仓库洞察 Insights

仓库的 Insights 标签可以查看：

  • Traffic：访问量、克隆量、热门内容（需写权限）。
  • Contributors：提交趋势与贡献者分布。
  • Community Standards：README、许可证、贡献指南、行为准则的完整度检查。
  • Dependency graph：依赖关系与漏洞来源。

官方学习资源

  • GitHub Skills：交互式实战课程，直接在仓库里练习。
  • github/docs：官方文档仓库，可以提 Issue 或 PR 纠错。
  • GitHub Education：学生与教师可申请 Copilot 等免费权益。
