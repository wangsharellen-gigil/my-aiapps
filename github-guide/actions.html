GitHub Actions 自动化

Actions 是 GitHub 内置的自动化平台：代码一推送，它就按你写的规则自动跑测试、打包、发版、部署网站。不用买服务器，配置文件就是仓库里的一个 YAML 文件。

六个核心概念

Workflow 工作流
一个自动化流程，对应 .github/workflows/ 下的一个 YAML 文件。
Event 事件
触发条件，例如 push、pull_request、定时任务、手动点击。
Job 作业
工作流里的一个任务单元，默认并行执行，可配置先后依赖。
Step 步骤
作业内的具体动作，按顺序执行。要么运行命令（run），要么调用现成的 Action（uses）。
Action 动作
可复用的功能模块，例如检出代码、安装 Node、上传构建产物。Marketplace 上有数万个。
Runner 运行器
真正执行任务的机器。GitHub 提供 Ubuntu / Windows / macOS 托管机器，也支持自建。

第一个工作流

在仓库里新建文件 .github/workflows/ci.yml：

name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: 安装依赖
        run: npm ci

      - name: 运行测试
        run: npm test

提交并推送后，打开仓库的 Actions 标签页，就能看到一次运行记录。点击进去可以展开每个步骤的实时日志。

说明

npm ci 与 npm install 的区别：ci 严格按 package-lock.json 安装，速度更快、结果可复现，适合 CI 环境。

YAML 关键语法

触发条件 on

on:
  push:
    branches: [main]
    paths: ["src/**", "package.json"]   # 只有这些文件变化才触发
  pull_request:
    types: [opened, synchronize, reopened]
  schedule:
    - cron: "0 2 * * *"                 # 每天 UTC 02:00（北京时间 10:00）
  workflow_dispatch:                     # 允许在网页上手动触发
    inputs:
      environment:
        description: "部署环境"
        default: staging

运行环境 runs-on

runs-on: ubuntu-latest    # 最常用，速度快、免费额度高
runs-on: windows-latest
runs-on: macos-latest

步骤：run 与 uses

steps:
  - uses: actions/checkout@v4          # 使用现成 Action
  - run: |                             # 执行多条命令
      echo "当前分支：$GITHUB_REF_NAME"
      ls -la
  - name: 使用密钥
    run: ./deploy.sh
    env:
      API_KEY: ${{ secrets.API_KEY }}   # 引用仓库密钥

矩阵测试：一次跑多种环境

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        node: [18, 20, 22]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
      - run: npm ci
      - run: npm test

上面会生成 3 × 3 = 9 个并行作业，任一组失败不影响其他组（fail-fast: false）。

密钥与环境变量

在仓库 Settings → Secrets and variables → Actions 中添加：

  • Secrets：加密存储，日志中自动打码，例如 DEPLOY_TOKEN、NPM_TOKEN。
  • Variables：明文配置，例如 API_BASE_URL。
      - run: echo "${{ vars.API_BASE_URL }}"
      - run: curl -H "Authorization: Bearer ${{ secrets.API_KEY }}" https://api.example.com
重要

不要用 echo 打印密钥、不要把密钥写进 YAML。来自 Fork 的 pull_request 工作流不会获得密钥（这是安全设计），需要密钥的操作请用 workflow_run 或由维护者手动触发。

最小权限原则

默认的 GITHUB_TOKEN 权限可能过大。建议在工作流顶部显式声明：

permissions:
  contents: read

jobs:
  build:
    permissions:
      contents: read
      pull-requests: write   # 只有需要评论 PR 的作业才开写权限

产物、缓存与依赖

      # 缓存依赖，加速后续构建
      - uses: actions/cache@v4
        with:
          path: ~/.npm
          key: ${{ runner.os }}-npm-${{ hashFiles('**/package-lock.json') }}

      # 上传构建产物，可在运行页面下载
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist/

      # 下载其他作业上传的产物
      - uses: actions/download-artifact@v4
        with:
          name: dist
          path: dist/

常见用途：自动部署 Pages

把静态站点推送到 gh-pages 分支或直接用官方 Pages Action，详见GitHub Pages 建站。核心片段：

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: ./site
      - id: deployment
        uses: actions/deploy-pages@v4

进阶能力一览

  • 作业依赖：needs: build 让部署等待构建完成。
  • 条件执行：if: github.ref == 'refs/heads/main'。
  • 并发控制：concurrency: { group: pages, cancel-in-progress: true } 避免重复部署。
  • 定时任务：schedule + cron，用于每日构建、数据同步。
  • 可复用工作流：uses: owner/repo/.github/workflows/x.yml@v1。
  • 复合 Action：把重复步骤封装成自己的 Action。
  • 自建 Runner：需要特殊硬件或内网访问时使用。
  • OIDC 免密钥部署：用短期凭证访问云服务，无需长期密钥。

排查失败

  1. 打开失败的运行记录，展开红色步骤查看完整日志。
  2. 常见原因：依赖版本不对、缺少环境变量、路径大小写不一致（Linux 区分大小写，Windows 不区分）。
  3. 点击 Re-run jobs 重跑；开启 Debug logging 可获得更详细日志（需设置 secret ACTIONS_STEP_DEBUG=true）。
  4. 用 workflow_dispatch 手动触发，缩短调试循环。
  5. 本地可用 act 工具模拟运行，但不是 100% 一致。

免费额度

  • 公开仓库：标准托管 Runner 免费，不限分钟数（合理使用范围内）。
  • 私有仓库：免费账号每月 2000 分钟，按操作系统倍率计费（Windows / macOS 消耗更快）。
  • 存储产物与包也有额度，超出后按量计费。
注意

不要在工作流里执行来源不明的脚本，也不要给 pull_request_target 工作流检出并运行 PR 中的代码——这是历史上真实发生过的供应链攻击入口。
