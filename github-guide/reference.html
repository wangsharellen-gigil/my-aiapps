常见报错与解决

Permission denied (publickey)

SSH 认证失败。依次检查：

  1. ssh -T git@github.com 是否成功。
  2. 公钥是否已添加到 GitHub（Settings → SSH and GPG keys）。
  3. ssh-add -l 是否加载了正确的私钥。
  4. 远程地址是否是 SSH 格式（git@github.com:...）。用 HTTPS 地址却配置 SSH 密钥也会失败。

Authentication failed / Password authentication is not supported

GitHub 已不支持密码推送。改用 PAT 或 SSH：

# 清除系统里保存的旧密码
git credential-manager delete https://github.com   # Windows
git credential-osxkeychain erase                   # macOS
# 或直接修改远程地址为 SSH
git remote set-url origin git@github.com:用户名/仓库.git

! [rejected] ... (fetch first)

远程有你本地没有的提交。不要强推，先同步：

git pull --rebase origin main
git push

fatal: refusing to merge unrelated histories

本地仓库和远程仓库是两段独立历史（常见于先 git init 又建了一个带 README 的远程仓库）。可以合并但保留两段历史：

git pull origin main --allow-unrelated-histories
# 解决可能的冲突 → add → commit → push

Your local changes would be overwritten by merge

git stash          # 保存当前改动
git pull
git stash pop      # 恢复改动，可能需要解决冲突

You are in 'detached HEAD' state

你直接检出了某个提交或标签，而不是分支。如果只是想看看，直接切回分支即可；如果在这里做了提交，先建分支保存：

git switch -c 新分支名
# 或放弃当前状态
git switch main

file is 123.00 MB; this exceeds GitHub's file size limit of 100 MB

GitHub 单文件上限 100 MB。处理方式：

  • 从提交中移除该文件，加入 .gitignore。
  • 如果必须管理大文件，使用 Git LFS：git lfs install && git lfs track "*.psd"。
  • 如果已经提交进历史，需要改写历史（git filter-repo）。

remote: Permission to ... denied to ...（403）

  • 你对目标仓库没有写权限：先 Fork，再向自己的 Fork 推送。
  • Token 权限不足：重新生成，勾选 repo 与需要的额外 scope。
  • 组织开启了 SSO：在 Token 设置页点击 Configure SSO 授权该组织。

remote origin already exists

git remote set-url origin 新地址
# 或先删除再添加
git remote remove origin
git remote add origin 新地址

warning: LF will be replaced by CRLF

只是换行符提示，不影响使用。按系统设置一次即可：Windows git config --global core.autocrlf true，macOS/Linux input。

GitHub Pages 一直 404

  • 确认 Pages 设置里的分支与目录正确，且入口文件名为 index.html。
  • 等待 1—2 分钟，构建需要时间；在 Actions 里查看 pages build and deployment 状态。
  • 项目站点地址必须带仓库名：用户名.github.io/仓库名/。
  • 资源 404 通常是绝对路径导致，改用相对路径。

SSL certificate problem / OpenSSL SSL_read

多数是网络代理或证书问题。先确认网络环境；临时排查可尝试切换 HTTPS/SSH 协议，或检查系统时间是否正确。不要盲目关闭 SSL 校验，那会带来安全风险。

常见问题

如何删除一个仓库？

仓库 Settings → 最下方 Danger Zone → Delete this repository，输入仓库全名确认。删除后 Fork 关系与 Issue 也会消失，且无法恢复。

如何重命名仓库或用户名？

仓库：Settings 顶部 Rename。用户名：Settings → Account → Change username。GitHub 会为重定向保留一段时间，但依赖旧地址的脚本、Pages 链接需要同步更新。

如何把公开仓库改为私有？

Settings → Danger Zone → Change repository visibility。注意：改为私有后，Pages 站点会下线，Actions 分钟数会计入私有仓库额度，已有的 Fork 不会自动变为私有。

误删了分支 / 提交还能找回吗？

本地可以用 git reflog 找到提交编号，再 git switch -c 分支名 提交编号。远程已删除的分支，如果近期在网页上操作过，可在仓库 Activity 或 PR 记录里找到提交 SHA。

已经推送的提交如何撤销？

用 git revert 提交号 生成一次反向提交再推送。只有在你独占的分支上，才考虑 reset + push --force-with-lease。

仓库太大怎么办？

检查是否误提交了依赖目录、构建产物或大文件；用 git count-objects -vH 查看体积，用 git filter-repo 清理历史，必要时改用 Git LFS。

没有编程基础可以贡献开源吗？

可以。文档纠错、翻译、设计、复现 Bug、整理 Issue 都是有价值的贡献。从 good first issue 标签开始最稳妥。

私有仓库能用 Pages 吗？

发布 Pages 需要 GitHub Pro / Team / Enterprise 等付费方案；免费账号请使用公开仓库。无论仓库是否私有，Pages 站点本身都是公开可访问的。

术语表

Repository
仓库，项目及其完整历史的集合。
Commit
提交，一次改动的快照，含作者、时间与说明。
Branch
分支，指向某次提交的可移动指针，用来隔离开发线。
main
默认主分支名称，旧项目可能仍叫 master。
origin
本地对默认远程仓库的别名。
upstream
Fork 场景中指向原仓库的别名。
HEAD
当前所在提交/分支的指针。
Stage / Index
暂存区，提交前的缓冲区。
Merge
合并，把两条分支历史连接起来。
Rebase
变基，把自己的提交重新接到另一条历史之后。
Conflict
冲突，Git 无法自动决定保留哪部分改动。
Fork
在 GitHub 上复制他人仓库到自己账号下。
Pull Request
合并申请，附带讨论、评审与自动检查。
Issue
任务/问题跟踪条目。
Tag
给某次提交起的固定名字，常用于版本号。
Release
基于 Tag 的发布页，可附安装包与说明。
CI / CD
持续集成 / 持续交付，自动化测试与部署。
Workflow
Actions 中的一个自动化流程。
Runner
执行 Actions 作业的机器。
LFS
Git Large File Storage，管理大文件的扩展。
