Issue 与 Discussions

Issue 是 GitHub 的"任务与问题跟踪器"。它不只用来报 Bug——需求、待办、讨论、文档勘误，都可以是一条 Issue。

Issue 能做什么

  • 记录 Bug，附带复现步骤与环境信息。
  • 提出新功能需求，收集其他人的反馈（👍 反应）。
  • 拆分开发任务，用勾选框跟踪进度。
  • 作为讨论区，沉淀"为什么这样设计"的决策记录。

创建一条 Issue

  1. 进入仓库，点击 Issues 标签页 → New issue。
  2. 填写标题（一句话说清问题）和正文（Markdown）。
  3. 在右侧栏设置 Assignees（负责人）、Labels（标签）、Milestone（里程碑）、Projects（看板）。
  4. 点击 Create 提交。也可以用 Create more 连续录入。

一份好的 Bug 报告通常包含：

**环境**
- 浏览器：Chrome 131 / iPhone 15 Safari
- 系统：Windows 11 / iOS 18

**复现步骤**
1. 打开首页
2. 点击右上角菜单
3. 再次点击空白处

**期望结果**
菜单关闭。

**实际结果**
菜单保持打开，必须刷新页面。

**截图 / 日志**
（附上截图或控制台报错）
提示

正文支持直接粘贴截图。GitHub 会自动上传图片并生成 Markdown 链接，不需要图床。

标签与里程碑

Labels（标签）用于分类。新仓库自带一组默认标签，也可以自定义颜色与名称：

  • bug：功能不符合预期。
  • enhancement：新功能或改进。
  • documentation：文档相关。
  • good first issue：适合新手认领，开源项目常用它标记入门任务。
  • help wanted：作者希望有人协助。
  • question：需要进一步信息。

Milestones（里程碑）用于把一批 Issue 归到同一个目标下，例如"v1.0 发布"，页面会自动显示完成百分比与剩余天数。

任务清单

- [x] 设计接口
- [x] 完成后端实现
- [ ] 补前端页面
- [ ] 编写测试

勾选后进度会实时保存并把完成度显示在 Issue 列表中，很适合把一个大 Issue 拆成子任务。

关联与自动关闭

在 Issue、PR 或提交信息里引用编号即可建立双向链接：

# 同一仓库
修复了 #12 中描述的崩溃问题

# 跨仓库
参考 owner/repo#45 的实现

# 合并自动关闭
Closes #12
Fixes #12
Resolves #12

当包含关闭关键词的 PR 被合并，对应 Issue 会自动关闭并注明"由 #PR编号 关闭"。

用搜索快速找到 Issue

is:open is:issue label:bug
is:open assignee:@me
is:closed label:documentation
author:用户名 is:pr created:>2026-01-01
no:label is:open

这些过滤器在仓库的 Issues 页面顶部搜索框、全局搜索里都通用。

Issue 模板

开源项目通常会在 .github/ISSUE_TEMPLATE/ 下放置模板，让提问者按格式填写，减少来回追问。最简单的方式是在仓库 Settings → Features → Issues → Set up templates 里用界面生成。

.github/
├── ISSUE_TEMPLATE/
│   ├── bug_report.yml        # Bug 表单
│   ├── feature_request.yml   # 功能建议表单
│   └── config.yml            # 模板选择页配置（可加外部链接）
└── PULL_REQUEST_TEMPLATE.md  # PR 模板

YAML 表单支持下拉框、必填项、自动打标签，比纯 Markdown 模板更规范。

Discussions：更轻的讨论区

Discussions 是仓库内的论坛式讨论区，适合"没有明确结论、需要多人交流"的话题。在仓库 Settings → Features 中勾选启用。

场景用 Issue用 Discussions
明确的 Bug 或具体任务✓
"怎么做才好？"开放式提问✓（Q&A 分类）
使用求助、经验交流✓
需要被排期、指派、跟踪进度✓
公告、投票、展示作品✓

Discussions 支持分类（Categories）、问答式"采纳最佳答案"、投票和把 Discussion 转为 Issue。反过来，Issue 也能一键转为 Discussion。

维护 Issue 的小习惯

  • 及时回复：哪怕是"已收到，本周处理"。
  • 合并重复：把重复 Issue 标记为 duplicate 并链接到原始 Issue。
  • 关闭而非堆积：无法复现的用 Close as not planned，附上原因。
  • 定期整理：给长期无人处理的 Issue 打上 stale 标签。
  • 用 Projects 看板：把 Issue 拖入"待办 / 进行中 / 已完成"列，进度一目了然（见更多平台功能）。

通知与订阅

参与过的 Issue 默认会订阅更新。可以在 Issue 右侧的 Subscribe / Unsubscribe 手动切换，或在 Settings → Notifications 中设置只接收"参与、@提及、被指派"的通知，避免邮件过载。
