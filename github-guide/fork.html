参与开源项目：Fork 与同步

你没有别人仓库的写权限，但仍然可以为它做贡献。Fork 就是把别人的仓库复制一份到你自己的账号下，改完后再通过 Pull Request 送回原项目。

Fork、Clone、Branch 的区别

概念位置作用
ForkGitHub 服务器上在你的账号下创建原仓库的完整副本，拥有写权限。
Clone本地电脑把某个仓库（自己的或 Fork 来的）下载到本地。
Branch仓库内部在同一个仓库里隔离不同改动，用于一个功能或一次修复。

典型链路是：Fork → Clone 到本地 → 新建分支 → 提交 → 推送到自己的 Fork → 向原仓库发 PR。

找到一个适合上手的项目

  • 在 GitHub 搜索 label:"good first issue"，这是维护者专门标记给新手的任务。
  • 浏览 Topics，按语言或领域找项目。
  • 从你正在使用的工具入手：文档有错字、示例跑不通，都是很好的第一个贡献。
  • 先读项目的 CONTRIBUTING.md（贡献指南）和 CODE_OF_CONDUCT.md（行为准则）。
提示

修复文档错别字、补充安装说明、翻译 README，都是被广泛接受的第一份贡献。不要一上来就重构核心代码，小改动更容易被合并。

完整贡献流程

1. Fork 仓库

打开目标仓库，点击右上角的 Fork → Create a new fork。默认会把仓库复制到你的账号下，名称相同。完成后你拥有 github.com/你的用户名/仓库名 的完整写权限。

2. 克隆到本地并配置上游

git clone https://github.com/你的用户名/仓库名.git
cd 仓库名

# 把原仓库添加为 upstream（上游），方便后续同步
git remote add upstream https://github.com/原作者/仓库名.git
git remote -v
# origin    你的 Fork
# upstream  原仓库

3. 新建分支并修改

git switch -c fix/typo-in-readme
# 修改文件……
git add .
git commit -m "docs: 修正 README 中的拼写错误"

4. 推送到自己的 Fork

git push -u origin fix/typo-in-readme

5. 向原仓库发起 PR

  1. 打开你的 Fork 页面，会出现 Compare & pull request 提示。
  2. 确认 base repository 是原仓库、base 分支是 main。
  3. 填写标题与说明，引用相关 Issue（如 Closes #88）。
  4. 提交后等待维护者评审。
说明

跨仓库 PR 默认允许维护者修改你的分支（"Allow edits by maintainers"）。保持勾选可以减少沟通成本。

保持 Fork 与上游同步

原项目会不断有新提交。长期不同步，你的分支会落后，PR 就容易冲突。

命令行方式

git switch main
git fetch upstream
git merge upstream/main       # 或 git rebase upstream/main
git push origin main

网页方式

在你 Fork 的仓库首页，如果落后于上游，会出现 Sync fork 按钮，点击 Update branch 即可。注意：如果该分支已经开了 PR，同步会改写分支内容，但通常没有问题。

只同步自己的功能分支

git switch fix/typo-in-readme
git fetch upstream
git rebase upstream/main
git push --force-with-lease

开源贡献的礼仪

  • 先讨论，再动手：大改动先开 Issue 说明思路，避免白写。
  • 一次 PR 只做一件事：格式化和功能修复分开提交。
  • 遵守项目规范：代码风格、提交信息格式、测试要求，先读 CONTRIBUTING。
  • 耐心等待：维护者多为志愿者，几天没有回复很正常，一周后可礼貌地 ping 一次。
  • 接受被拒绝：维护者有权不接受某个改动，这不代表你的努力没价值。
注意

不要给开源项目提交包含密钥、内部链接或与项目无关的广告内容。被标记为 spam 会影响账号信誉。

如果你成了维护者

当你的项目开始有人提 PR，可以配置这些机制降低维护成本：

  • PR 模板：.github/PULL_REQUEST_TEMPLATE.md，提示贡献者填写验证方式。
  • 自动标签：用 Actions 给新 Issue / PR 自动打标签、分配评审人。
  • 分支保护：要求 CI 通过 + 至少一人批准。
  • 贡献指南：把"如何本地运行、如何跑测试"写清楚。
  • 行为准则：明确社区交流的底线。

Star、Watch、Fork 有什么不同

动作含义
Star收藏并表达喜欢，会出现在你的 Stars 列表，也影响项目热度。
Watch订阅动态，有新 Issue / PR / 发布会通知你。可选 Only releases 等粒度。
Fork复制到自己账号下，准备修改或二次开发。
