什么是 Git 与 GitHub

在动手之前，先用几分钟把几个关键词弄清楚。理解它们之间的关系，后面的命令就不再是"死记硬背的咒语"。

为什么需要版本控制

你一定见过这样的文件名：

毕业论文_最终版.docx
毕业论文_最终版_修改.docx
毕业论文_最终版_真的最终.docx
毕业论文_最终版_导师改过的.docx

靠复制文件来保存历史，会带来三个问题：不知道改了什么、不知道谁改的、想退回上一版时找不到。多人协作时问题更严重——两份文件合并几乎只能靠手工。

版本控制工具（Version Control System）就是为了解决这些问题：它把每一次有意义的改动打包成一个提交（commit），记录改动内容、作者、时间和说明；你随时可以查看历史、对比差异、退回到任意一个版本。

Git 是什么

Git 是一个分布式版本控制系统，由 Linux 的创始人 Linus Torvalds 在 2005 年开发。它安装在你的电脑上，负责在本地记录文件变化。

"分布式"的意思是：每个人电脑上都有一份完整的项目历史，不依赖中央服务器。即使断网，你也能提交、查看历史、切换分支；联网后再和别人同步。

三个区域，一条主线

Git 把文件的状态分成三个区域。日常操作本质上就是把改动从一个区域挪到下一个区域：

工作区你正在编辑的文件
→
暂存区挑出这次要提交的改动
→
本地仓库提交后写入历史
→
远程仓库推送到 GitHub

对应到命令就是：改文件（工作区）→ git add（放入暂存区）→ git commit（写入本地仓库）→ git push（上传到远程仓库）。这条链路会贯穿整个指南。

提示

暂存区不是多余的步骤。它让你可以只提交"这次相关的改动"，比如你顺手改了三个文件，但只想提交其中一个，git add 就能精确控制。

GitHub 是什么

GitHub 是一个基于 Git 的代码托管与协作平台，2008 年上线，2018 年被微软收购。它把 Git 仓库放在云端，并围绕仓库提供了大量协作功能：

  • 托管：仓库、发布包、静态网站、容器镜像。
  • 协作：Issue 跟踪任务、Pull Request 评审代码、Projects 管理进度。
  • 自动化：Actions 运行测试与部署，Dependabot 自动升级依赖。
  • 社区：Star、Fork、关注、Discussions、个人主页。

两者的区别与联系

对比项GitGitHub
是什么版本控制工具（软件）代码托管与协作平台（网站/服务）
在哪里安装在你自己的电脑上运行在云端，用浏览器或客户端访问
谁维护开源社区GitHub 公司（微软旗下）
能否离线可以，本地功能完整不能，需要联网
是否必须用 GitHub 就必须会用一点 Git不用 GitHub 也可以用 Git（如 GitLab、Gitee）

一句话总结：Git 负责"记住历史"，GitHub 负责"共享与协作"。你完全可以在本地只用 Git 不用 GitHub，但一旦要备份、协作或展示作品，就需要一个远程仓库，GitHub 是最常用的一种。

先认识六个核心概念

仓库 Repository
一个项目的"文件夹 + 全部历史"。GitHub 上的仓库就是网页上看到的项目页面。
提交 Commit
一次改动快照，包含改动内容、作者、时间戳和提交说明。历史就是由一串提交组成的。
分支 Branch
一条独立的开发线。默认分支通常叫 main。分支不是复制整个项目，而是一个指向某次提交的"指针"，所以创建和切换都非常快。
远程 Remote
托管在服务器上的仓库副本，通常命名为 origin。推送（push）和拉取（pull）都是与它交互。
克隆 Clone
把远程仓库完整复制到本地，包含全部历史，之后就可以在本地提交。
拉取请求 Pull Request
不是 Git 的功能，而是 GitHub 的功能：请求把自己的分支合并进目标分支，并在这个过程中进行讨论与代码评审。

GitHub 能做什么：功能地图

本指南后续章节会逐一展开，这里先建立一个全局印象：

写代码与存代码

  • 仓库、分支、提交历史
  • 网页版在线编辑与上传
  • Releases 发布版本
  • Packages 托管依赖包

协作与沟通

  • Issue 记录 Bug 与需求
  • Pull Request 评审合并
  • Projects 看板与路线图
  • Discussions 社区讨论

自动化与托管

  • Actions 持续集成与部署
  • Pages 免费静态网站
  • Codespaces 云端开发环境
  • Dependabot 依赖升级

个人与社区

  • 个人主页 README
  • Star / Follow / Fork
  • Gist 代码片段
  • Copilot AI 编程助手

给新手的三个建议

  1. 先跑通一个完整闭环：建仓库 → 改文件 → 提交 → 推送。哪怕只改一行字，闭环跑通后你会发现剩下的都是变体。
  2. 不要试图背下所有命令：掌握 10 个高频命令，其余随用随查。本指南附有速查表。
  3. 把练习放在公开仓库里：公开仓库可以免费使用 Actions 和 Pages，也方便你回看自己的成长轨迹。
