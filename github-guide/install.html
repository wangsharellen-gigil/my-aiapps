安装与配置 Git

这一篇把本地环境准备好：安装 Git、设置身份信息，并打通与 GitHub 的认证。认证是最容易卡住新手的环节，我们会把两种方式都讲清楚。

安装 Git

Windows

方式一（推荐）：打开 PowerShell，执行：

winget install --id Git.Git -e --source winget

方式二：到 git-scm.com/download/win 下载安装包，双击运行，一路保持默认选项即可。

安装完成后会多出两个程序：Git Bash（类 Linux 的命令行，推荐新手用它练习）和 Git CMD。在开始菜单搜索 "Git Bash" 打开。

macOS

系统自带 Git，但版本可能较旧。最简单的升级方式是安装 Xcode 命令行工具：

xcode-select --install

如果你使用 Homebrew，也可以：

brew install git

Linux

# Debian / Ubuntu
sudo apt update && sudo apt install git

# Fedora / RHEL
sudo dnf install git

# Arch
sudo pacman -S git

验证安装

git --version
# 输出示例：git version 2.47.1

能看到版本号就说明安装成功。

第一次配置：告诉 Git 你是谁

每次提交都会记录作者信息，所以必须先配置用户名和邮箱。这里的邮箱建议与 GitHub 账号一致（或使用 GitHub 提供的 noreply 邮箱）。

git config --global user.name "Wang Xiaoming"
git config --global user.email "your_email@example.com"

再设置两个对新手很友好的默认项：

# 新仓库的默认分支名使用 main（与 GitHub 保持一致）
git config --global init.defaultBranch main

# 让 Git 在 Windows 上正确处理换行符，避免满屏"整个文件都改了"
git config --global core.autocrlf true

macOS / Linux 用户把最后一行改为：

git config --global core.autocrlf input

查看当前配置：

git config --global --list
说明

--global 表示对当前用户的所有仓库生效。如果某个仓库需要用公司邮箱，可以在该仓库目录下不带 --global 再设置一次，局部配置会覆盖全局配置。

认证：GitHub 如何确认"你是你"

把代码推送到 GitHub 时，服务器需要验证身份。GitHub 早已不再支持用账号密码推送，只能用下面两种方式之一。

HTTPS + 个人访问令牌

  • 配置简单，走 443 端口，几乎不受网络限制
  • 需要生成并保存 Token
  • 适合新手、临时环境

SSH 密钥

  • 一次配置长期使用，不用反复输入
  • 不受 Token 过期影响
  • 适合长期开发

方式一：个人访问令牌（PAT）

  1. 登录 GitHub，进入 Settings → Developer settings → Personal access tokens。
  2. 选择 Tokens (classic) → Generate new token (classic)；或选择 Fine-grained tokens 做更细粒度的授权。
  3. 填写 Note（用途备注）和有效期，勾选权限：
    • 经典令牌：至少勾选 repo；需要触发 Actions 时再勾选 workflow。
    • 细粒度令牌：选择具体仓库，授予 Contents: Read and write。
  4. 点击生成，立刻复制以 ghp_ 或 github_pat_ 开头的字符串。
  5. 下次 git push 提示输入密码时，粘贴这个令牌作为密码，用户名填 GitHub 用户名。
重要

令牌等同于密码，只能保存在密码管理器或系统凭据里。绝对不要写进代码、提交到仓库、发在聊天群或截图里。一旦泄露，请立刻到设置页撤销并重新生成。

Windows 上 Git 会通过 Git Credential Manager 自动记住令牌，只需输入一次。macOS 使用钥匙串，Linux 可启用缓存：

# 记住 1 小时（单位：秒）
git config --global credential.helper 'cache --timeout=3600'

方式二：SSH 密钥（推荐长期使用）

先生成一对密钥（公钥 + 私钥），默认使用更现代、更短的 ed25519 算法：

ssh-keygen -t ed25519 -C "your_email@example.com"

连续回车即可（密码短语可留空，也可设置更安全的保护）。生成后启动 ssh-agent 并添加私钥：

# macOS / Linux / Git Bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Windows PowerShell（需以管理员身份启动 ssh-agent 服务）
Get-Service ssh-agent | Set-Service -StartupType Automatic
Start-Service ssh-agent
ssh-add $env:USERPROFILE\.ssh\id_ed25519

复制公钥内容（文件名以 .pub 结尾）：

# macOS
pbcopy < ~/.ssh/id_ed25519.pub

# Windows
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | Set-Clipboard

# Linux
cat ~/.ssh/id_ed25519.pub

然后到 GitHub：Settings → SSH and GPG keys → New SSH key，粘贴公钥并保存。测试连接：

ssh -T git@github.com
# 成功时输出：Hi 用户名! You've successfully authenticated...
注意

只能上传 .pub 公钥。私钥（没有 .pub 后缀的那个文件）永远不要发给任何人，也不要上传到任何网站。

克隆时用哪种地址

# HTTPS
https://github.com/用户名/仓库名.git

# SSH
git@github.com:用户名/仓库名.git

仓库页面绿色的 Code 按钮里可以切换两种地址。用 SSH 就选 SSH 地址，用令牌就选 HTTPS 地址，混用会认证失败。

可选：安装 GitHub CLI

官方命令行工具 gh 把常见操作（建仓库、开 PR、看 Actions 日志）搬到了终端，登录一次即可同时配置好 Git 凭据：

# Windows
winget install --id GitHub.cli

# macOS
brew install gh

# 登录（选择 HTTPS 或 SSH，按提示在浏览器中授权）
gh auth login

配置检查清单

  • git --version 能输出版本号。
  • git config --global user.name 与 user.email 已设置。
  • 已生成 PAT 或配置好 SSH，并用 ssh -T git@github.com 验证通过。
  • 知道自己的默认分支是 main。
提示
