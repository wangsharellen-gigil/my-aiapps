GitHub Pages 免费建站

GitHub Pages 可以把仓库里的静态文件直接发布成网站。个人主页、项目文档、作品集、博客，都可以托管在这里，免服务器、免备案（使用默认域名时）、手机电脑都能访问。

它能做什么，不能做什么

适合

  • HTML / CSS / JS 静态网站
  • Jekyll、Hugo、VitePress 等生成的静态站
  • 项目文档、个人简历、作品集
  • 前后端分离项目的前端页面

不适合

  • 需要数据库或后端服务的应用
  • 需要登录态、支付、私密数据
  • 大文件下载站（有流量限制）
  • 私密内容（Pages 站点是公开的）

两种站点地址

类型仓库命名访问地址
用户/组织站点你的用户名.github.iohttps://你的用户名.github.io
项目站点任意仓库名https://你的用户名.github.io/仓库名

一个账号只能有一个用户站点，但可以有无数个项目站点。每个账号的 Pages 站点总大小建议不超过 1 GB，每月流量约 100 GB。

方式一：从分支发布（最简单）

  1. 把网站文件提交到仓库。入口文件必须是仓库某个目录下的 index.html。
  2. 进入仓库 Settings → 左侧 Pages。
  3. 在 Build and deployment 的 Source 选择 Deploy from a branch。
  4. Branch 选择 main，目录选择 / (root) 或 /docs，点击 Save。
  5. 等 1—2 分钟，页面上方会出现 Your site is live at ...，点击链接即可访问。
仓库结构示例（发布目录选 / (root)）
.
├── index.html
├── about.html
├── assets/
│   ├── style.css
│   └── main.js
└── .nojekyll
提示

如果发布目录选 /docs，请把网站文件放进 docs/ 文件夹，仓库根目录仍可放源码。这在"源码 + 构建产物"同仓库的项目里很常用。

关于 .nojekyll

默认情况下 Pages 会用 Jekyll 处理一遍文件，凡是以下划线开头的文件或目录（如 _next/）会被忽略。如果你的站点不需要 Jekyll，在发布目录放一个空的 .nojekyll 文件即可关闭处理、原样发布。

方式二：用 Actions 发布（推荐用于构建型项目）

适合 React / Vue / Vite / Hugo 等需要构建的站点。先到 Settings → Pages → Source 选择 GitHub Actions，再添加工作流：

name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4

之后每次推送到 main，都会自动构建并发布。运行记录在 Actions 页面的 pages build and deployment 中查看。

注意

项目站点部署在子路径 /仓库名/ 下。构建工具需要配置 base（Vite）或 homepage（Create React App），否则 CSS 和 JS 会 404。若不想处理，改用用户站点仓库即可部署在根路径。

路径写法：最容易踩的坑

假设站点地址是 https://用户名.github.io/my-site/：

<!-- 错误：会去根域名找资源 -->
<link rel="stylesheet" href="/assets/style.css">

<!-- 正确：相对路径 -->
<link rel="stylesheet" href="assets/style.css">
<link rel="stylesheet" href="./assets/style.css">

页面之间的链接同理，使用相对文件名（如 about.html）而不是以 / 开头的绝对路径。本指南就是按这个规则编写的，可以直接部署到任意子目录。

绑定自定义域名

  1. 在 Settings → Pages → Custom domain 填入域名，例如 docs.example.com，保存后会生成 CNAME 文件。
  2. 到域名服务商添加解析记录：
    • 子域名（docs.example.com）：添加 CNAME 记录指向 你的用户名.github.io。
    • 根域名（example.com）：添加 4 条 A 记录，指向 185.199.108.153、185.199.109.153、185.199.110.153、185.199.111.153；或使用 ALIAS/ANAME。
  3. 等 DNS 生效（几分钟到 24 小时），回到 Pages 设置勾选 Enforce HTTPS。

自定义域名使用 HTTPS 需要证书签发，通常几分钟内完成。国内域名使用自有域名访问时，请遵守当地关于网站备案的规定。

常见问题排查

现象原因与处理
访问返回 404没选对发布目录、入口不是 index.html、或构建失败。先看 Actions / Pages 页面的部署状态。
页面能开但样式丢失资源用了以 / 开头的绝对路径，改成相对路径。
改完代码网站没变等待 1—2 分钟；强制刷新（Ctrl/Cmd + Shift + R）；确认推送的是发布分支。
构建失败并收到邮件查看 Actions 日志，常见是依赖安装失败或 Node 版本不匹配。
Enforce HTTPS 灰色不可选证书还在签发，等几分钟；确认 DNS 已正确指向。
下划线开头的目录 404添加空的 .nojekyll 文件。

使用限制（官方说明摘要）

  • 站点建议不超过 1 GB，每月流量建议不超过 100 GB。
  • 每小时最多构建 10 次。
  • 仅用于静态托管，不允许作为在线商城、敏感交易等用途。
  • 私有仓库发布 Pages 需要付费方案；公开仓库免费。
提示

本站就是一套纯静态站点：克隆仓库后开启 Pages 即可得到一模一样的效果。实践中遇到问题，可以回到 常见报错 或在本站仓库提 Issue。
